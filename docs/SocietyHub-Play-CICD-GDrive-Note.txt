============================================================

               Closed testing: 12 testers for 14 days before Google unlocks
               "Apply for production".

  iOS (local only)
    Bundle:    com.societyhub.societyhubMobile
    Status:    Simulator / signed Debug on a device. NO TestFlight / App Store.
    CI IPA:    Off until ENABLE_IOS_IPA=true + Apple Developer $99 + ASC secrets.

GitHub Actions workflow "Mobile CI" (.github/workflows/mobile.yml) can:
  1) flutter analyze + test     (every PR/push that touches apps/mobile)
  2) Sign a release AAB         (upload keystore in GitHub secrets)
  3) Upload + roll out Play INTERNAL  (testers who opted in can install)

CI never publishes Production.

Git flow (do not skip):
  feature/…  →  PR  →  staging  →  Promote preview  →  main  →  Render
Play store jobs may run from staging or main. Render API only updates after
Promote preview merges staging into main.

============================================================
HOW TO RUN A STORE BUILD
============================================================
1. Land the code: PR into staging, wait until CI + Mobile analyze/test are green.
2. If testers should hit new API/web too: Actions → Promote preview
   (staging → main → Render). Hobby cold start ~60s.
3. GitHub → Actions → Mobile CI → Run workflow
     Use workflow from:  staging  (or main after promote)
     Build IPA:          false
     Upload to Play:     true
4. Watch the run: Analyze and test → Android AAB → Play internal.
   AAB/Play are skipped on pull_request; they only run on this dispatch
   (or a mobile-v* tag).

Result:
  Artifact societyhub-android-aab
  Play Console → Internal testing → release is live for opted-in testers
  Closed testing testers and Production stay Console clicks.

Local AAB (same signing), if CI is down:
  cd apps/mobile
  flutter build appbundle --release \
    --dart-define=ENV=prod \
    --dart-define=API_BASE_URL=https://societyhub-api-ece6.onrender.com \
    --dart-define=GOOGLE_SERVER_CLIENT_ID=<web-oauth-client-id> \
    --dart-define=PRIVACY_POLICY_URL=https://societyhub-client.onrender.com/privacy
  Output: apps/mobile/build/app/outputs/bundle/release/app-release.aab

============================================================
VERIFY AFTER AN INTERNAL UPLOAD
============================================================
1. Play Console → Internal testing → latest release = 1.0.3 (or the
   version you just shipped). Testers get an update (or the opt-in link).
2. On a tester phone, open SocietyHub → login (real OTP / Google / password).
   Store builds must talk to https://societyhub-api-ece6.onrender.com
   (DEV_AUTH should be false on that API).
3. Smoke: raise a complaint; Account → Family shows people, not only counts.
   Chairperson with a linked flat must see the household list (API GET
   /v1/household/members).
4. If login "network" / timeout: Render Hobby may be cold — wait ~60s,
   open https://societyhub-api-ece6.onrender.com/health then retry.

Local (not Play) check — Mac + emulator/Simulator:
  See README.md "Check / test local Android and iOS"
  Android emulator API:  http://10.0.2.2:3000
  iOS Simulator API:     http://127.0.0.1:3000
  OTP when DEV_AUTH=true: 9999999999 / 8888888888  code 123456

IF SOMETHING BREAKS
============================================================
Play upload 403: invite play-upload@… in Play Console and wait ~5 min.
Play upload 401: JSON secret missing or wrong GitHub environment (must be prod).
AAB signing fail: ANDROID_KEYSTORE_* secrets on environment prod.
Analyze / test red: fix on the feature branch (flutter analyze, bun run quality).
  Common: Bun per-file coverage <90%; Flutter analyze treats info as fail.
Google Sign-In fail on Play build (no idToken / "could not verify"):

  Classical Play SHA-1 was already registered (Create said in use).

  App still uses the Web client as serverClientId. Never paste an Android
